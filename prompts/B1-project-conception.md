# Independent scientific project conception

## Inputs supplied by the adviser

- Lead scientist's idea, context and known constraints: `[insert text or reference INPUT.md]`
- Available source/data packet, if any: `[path, or none]`
- Save your conception brief to: `[your output path]`

## Assignment

Develop this idea (or partial project, if a baseline repository is supplied) independently into the strongest worthwhile, feasible and scientifically defensible investigation or scientific-software contribution it can support. Challenge the initial formulation—and any existing implementation or assumptions—where evidence warrants. Define the intended contribution and epistemic standards, not a predetermined result or a detailed implementation plan.

Consider:

1. Which scientific questions or research/software contributions are most promising, and why do they matter relative to existing work?
2. What would constitute a substantial, publishable or adoptable contribution rather than an incremental addition?
3. What minimum defensible outcome would justify calling the project complete and ready to reach its audience? Which optional stretch goals would add real value without blocking completion?
4. What evidence, data, benchmarks, validation or falsifiable checks would be needed? What would a negative, null or infeasible result mean for a worthwhile conclusion?
5. Which conceptual weaknesses, bottlenecks, assumptions, novelty questions, data limitations or resource constraints could require reformulation, simplification, or stopping?

Develop two or three distinct project conceptions and recommend one, or recommend against proceeding if warranted. Be explicit about what is established from inspected sources, what is assumed, and what remains unknown.

## Preliminary checks and boundaries

- **Bounded checks only:** You may inspect the supplied workspace/packet and run a tightly bounded preliminary check of novelty, competing tools/literature or data availability (e.g., targeted primary-source lookups). Cite only sources you actually inspect, disclose access limits, and label unverified novelty claims as unverified rather than presenting training memory as a literature search.
- **No execution or edits:** Do not begin coding, modify repository files, install environments, run simulations/benchmarks, create infrastructure or collect a new dataset.
- **Strict isolation:** Work completely independently. Do **not** query or post to any Correspondence Board (via MCP or otherwise), read peer workspaces (`~/codex/`, `~/claude/`, `~/gemini/`), inspect the adviser repository (`~/work/research-advisor`), read unrelated local repositories, rely on cross-workspace memory or prior chats on this topic, or add Git remotes / push.
- **Autonomy:** Exercise judgement and resolve ordinary uncertainty; raise a blocker only for a genuinely essential missing input. Do not infer that success must confirm the original idea.

## Output and stopping contract

Write the complete brief (~1,000–1,500 words) directly to `[your output path]` (do not return it only in chat, and touch no other files). Start with a concise header:

- `Common input:` `[baseline / packet identifier]`
- `Model / harness:` `[only what you can directly observe; do not guess or invent a model ID]`
- `External checks:` `[none, or brief list of live sources/lookups actually run]`
- `Status:` `ready for review` (or `blocked: <precise reason>`)

Stop after saving the file and give only a brief confirmation. The adviser and lead scientist will compare the three independent conceptions before commissioning the next stage.
